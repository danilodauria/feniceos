Perché due servizi: GitHub accetta file fino a 100 MB nel repository e fino a 2 GB nelle Release, e la ISO pesa 2,26 GB. SourceForge è gratuito, non ha questo limite per i progetti liberi e distribuisce i file da server in tutto il mondo: lo usano moltissime distribuzioni. Il sito resta su GitHub, accanto al Professore Digitale e al Grande Quiz, e il pulsante «Scarica» porta alla ISO su SourceForge.

  • La cartella feniceos che ti ho consegnato in Download: è il sito già pronto.
  • L'account GitHub danilodauria e GitHub Desktop (già pronti), un indirizzo email per SourceForge.
  • Una connessione stabile: il caricamento della ISO dura da 20 minuti a qualche ora.

2 · SourceForge: creare il progetto SOLO LA PRIMA VOLTA

  1. Vai su sourceforge.net → Join e crea l'account (nome utente, email, password). Conferma l'email che ti arriva.
  2. Da entrato, apri sourceforge.net/create (in alto: Create → Create a project).
  3. Compila così:
    Project NameFeniceOS
    URLfeniceos — esattamente così: il sito usa sourceforge.net/projects/feniceos. Se fosse già preso, scegline un altro (es. feniceos-linux) e dimmelo: aggiorno io il sito.
    DescriptionSistema operativo libero e gentile, basato su Debian 12 e MATE, che parte da chiavetta USB e dà nuova vita ai computer usati. Ideato da Danilo D'Auria.
  4. Clicca Create. Nella pagina del progetto, in Admin → Project Info puoi aggiungere la descrizione lunga, il link al sito (https://danilodauria.github.io/feniceos/) e il logo (docs/assets/fenice.svg esportato in PNG, o uno screenshot della scrivania).

3 · Caricare la ISO

3a · Dal browser (la strada più semplice)

  1. Nel progetto apri la scheda Files → Add Folder → scrivi 2.2 → Save. Il nome della cartella è il numero di versione: il sito si aspetta proprio 2.2.
  2. Entra nella cartella 2.2 → Add File → trascina FeniceOS_x64.iso e FeniceOS_x64.iso.sha256. Non chiudere la scheda finché la barra non è completa.
  3. Accanto alla ISO clicca l'icona i (informazioni) → in Default Download For spunta Windows, Mac, Linux, Others → Save. Così il grande pulsante verde «Download Latest Version» del progetto scarica la ISO.

3b · Dal PC Zorin con rsync (consigliato se il browser si interrompe)

rsync riprende da dove si era fermato se la connessione cade. Crea prima la cartella 2.2 dal browser (passo 1 qui sopra), poi nel Terminale, nella cartella con la ISO:

rsync -avP -e ssh FeniceOS_x64.iso FeniceOS_x64.iso.sha256 \
  TUONOMEUTENTE@frs.sourceforge.net:/home/frs/project/feniceos/2.2/

Alla prima connessione chiede di confermare la chiave del server (scrivi yes) e la password di SourceForge. Se si interrompe, rilancia lo stesso comando. Poi fai il passo 3 della sezione 3a (Default Download).

Dopo il caricamentoSourceForge copia il file sui suoi server nel mondo: il link di download può impiegare fino a mezz'ora per funzionare ovunque.

4 · Il sito danilodauria.github.io/feniceos SOLO LA PRIMA VOLTA

  1. Sposta la cartella feniceos da Download a Documenti\GitHub.
  2. In GitHub Desktop: File → Add local repository… → scegli Documenti\GitHub\feniceos. GitHub Desktop dice che non è ancora un repository: clicca «create a repository» → lascia tutto com'è (nome feniceos, senza README, .gitignore e licenza: ci sono già) → Create repository.
  3. In alto clicca Publish repository → nome feniceos → togli la spunta a «Keep this code private» → Publish repository. Questa volta «Publish» è giusto: il repository su GitHub non esiste ancora.
  4. Su github.com/danilodauria/feniceos → Settings → Pages → Source: Deploy from a branch → Branch main, cartella /docs → Save.
  5. Dopo 1–2 minuti il sito è su https://danilodauria.github.io/feniceos/. In Settings → General puoi aggiungere quell'indirizzo come «Website» del repository.

5 · Controllare che tutto funzioni

  1. Apri il sito: devono comparire versione 2.2, dimensione 2,26 GB e l'impronta che comincia con f5e269de.
  2. Clicca Scarica la ISO: deve aprirsi SourceForge e partire il download di FeniceOS_x64.iso.
  3. Apri il libretto e il libretto da stampare dalla sezione «Libretto, vademecum e guide».
  4. Da un telefono: la pagina si legge bene e i pulsanti si toccano facilmente.

6 · Una nuova ISO OGNI VOLTA

  1. Sul PC Zorin costruisci la ISO: sudo ./build_feniceos.sh (lo script sta anche nel repository, in strumenti/). Provala in VirtualBox.
  2. Nella cartella del repository feniceos aggiorna il sito con un comando (calcola dimensione e impronta e scrive tutto da solo): 
    python3 strumenti/aggiorna-iso.py ~/fenice_build/FeniceOS_x64.iso --versione 2.3
  3. Su SourceForge crea la cartella 2.3, carica la ISO e il nuovo .sha256 (che trovi in docs/download/), imposta il «Default Download».
  4. Se è cambiato anche il libretto, sostituisci i due PDF in docs/download/.
  5. Pubblica il sito: da Zorin git add -A && git commit -m "FeniceOS 2.3" && git push, oppure da Windows con GitHub Desktop (Commit, Push).
Correzioni veloci senza programmiPer cambiare solo un indirizzo, puoi anche modificare docs/dati/iso.json direttamente su github.com (icona della matita → «Commit changes»): il sito legge quel file a ogni apertura.

7 · Professore Digitale: i vademecum 3.5.3 sul sito

I due vademecum ora riportano la 3.5.3 e, nel vademecum per Linux, l'errore «Il server locale non si è avviato» con la soluzione. Vanno in due posti:

  1. Sorgenti: ho già copiato i 4 file (2 PDF in docs e 2 HTML in docs\sorgenti) nella tua copia Documenti\GitHub\professore-digitale. In GitHub Desktop vedrai 4 modifiche: Summary Vademecum aggiornati alla 3.5.3 → Commit to main → Push origin.
  2. Sito: in Download\ProfessoreDigitale-3.5.3-vademecum fai doppio clic su UNISCI.bat: ottieni il nuovo sito-3.5.3.zip. Su GitHub apri Releases → Professore Digitale 3.5.3 → ✏️ Edit, elimina il vecchio sito-3.5.3.zip (la ❌ accanto), trascina quello nuovo e clicca Update release.
  3. Apri Actions → Pubblica il sito → Run workflow, scrivi v3.5.3 e clicca Run workflow. Quando ha la spunta verde, i vademecum nuovi sono sul sito.

Da Zorin, con gh, gli stessi due passi del sito sono: gh release upload v3.5.3 sito-3.5.3.zip --clobber -R danilodauria/professore-digitale e gh workflow run pubblica-sito.yml -R danilodauria/professore-digitale -f versione=v3.5.3.
